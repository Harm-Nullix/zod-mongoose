# Strict Model

Use `toStrictModel()` when you want `.populate()` to change the TypeScript result type as you chain Mongoose queries. Start with ordinary [references](/guides/references-and-population); use this wrapper when population types become hard to track.

## Define every referenced path

Register the referenced Mongoose models before querying. The same schema below defines `author`, `author.user`, and `mentions`, so each population example has a real path.

```ts [strict-post.ts]
import mongoose from 'mongoose';
import {z} from 'zod/v4';
import {toMongooseSchema, toStrictModel, zRef} from '@nullix/zod-mongoose';

const UserSchema = z.object({username: z.string()});
const AuthorSchema = z.object({
  name: z.string(),
  user: zRef('Account', UserSchema),
});
const PostSchema = z.object({
  title: z.string(),
  author: zRef('Author', AuthorSchema),
  mentions: z.array(zRef('Author', AuthorSchema)),
});

mongoose.model('Account', toMongooseSchema(UserSchema));
mongoose.model('Author', toMongooseSchema(AuthorSchema));
const PostModel = toStrictModel('Post', toMongooseSchema(PostSchema));
```

## Populate one or more paths

These queries require an active MongoDB connection and build on the schemas above.

```ts [population-queries.ts]
const post = await PostModel.findOne({title: 'Hello'}).populate('author').exec();
if (post?.author) {
  console.log(post.author.name); // Typed as the populated Author document
}

const deepPost = await PostModel.findOne().populate('author.user').exec();
if (deepPost?.author?.user) {
  console.log(deepPost.author.user.username);
}

const withMentions = await PostModel.findOne()
  .populate('author mentions')
  .exec();

const withNestedOptions = await PostModel.findOne().populate({
  path: 'author',
  populate: {path: 'user'},
}).exec();
```

`toStrictModel(name, mongooseSchema)` infers the document type, query helpers, statics, instance methods, virtuals, and hydrated document overrides from the schema. Its query and document wrappers retain those extensions during population.

## Preserve schema extensions

Prefer inferring the types from the schema:

```ts
const postSchema = toMongooseSchema(PostSchema, {
  query: {
    byTitle(title: string) {
      return this.where({title});
    },
  },
});
const TypedPostModel = toStrictModel('TypedPost', postSchema);
const posts = await TypedPostModel.find().byTitle('Hello').populate('author').exec();
```

Existing `toStrictModel<Post>(name, schema)` calls remain supported. TypeScript uses the defaults for remaining generic parameters when only the first is supplied, so pass both types if you want an explicit document type and schema extensions:

```ts
const ExplicitPostModel = toStrictModel<z.infer<typeof PostSchema>, typeof postSchema>(
  'ExplicitPost',
  postSchema,
);
```

Inline fluent query helpers retain the current population state. Helpers with explicitly declared return types retain those signatures, including helpers that return a projection, a count, or a terminal value. `StrictDocument<DocType>`, `StrictQuery<Result, DocType>`, and `StrictModel<RawModel, DocType>` are exported types for advanced usage; most applications only need `toStrictModel()`.
